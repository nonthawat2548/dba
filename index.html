Constraint คือกฎที่ตั้งไว้ในตารางให้ฐานข้อมูลตรวจเอง เช่น ห้ามกรอกเงินเดือนติดลบ หรือห้ามใช้รหัสพนักงานซ้ำ เมื่อเพิ่มหรือแก้ข้อมูลแล้วไม่ผ่านกฎ คำสั่งนั้นจะไม่สำเร็จ แต่ละกฎตรวจคนละเรื่องดังตารางนี้
ข้อกำหนดตรวจอะไรสิ่งที่คนมักสับสน
NOT NULLคอลัมน์ต้องมีค่าไม่ได้บอกว่าค่าที่มีสมเหตุสมผลหรือไม่
UNIQUEค่าหรือชุดค่าที่กำหนดต้องไม่ซ้ำกับแถวอื่นไม่เท่ากับ NOT NULL; Oracle อนุญาต NULL ใน UNIQUE ได้
PRIMARY KEYระบุแต่ละแถวไม่ซ้ำและไม่เป็น NULLหนึ่งตารางมี PK ได้หนึ่งชุด แต่ชุดนั้นมีหลายคอลัมน์ได้
FOREIGN KEYค่าที่ใส่ต้องมีอยู่ในคอลัมน์ที่อ้างถึง เช่น รหัสแผนกต้องมีในตารางแผนกมี FOREIGN KEY แล้ว ยังใส่ NULL ได้ หากไม่ได้กำหนด NOT NULL เพิ่ม
CHECKปฏิเสธข้อมูลเมื่อเงื่อนไขให้ผลว่า “ไม่จริง” (FALSE)ถ้าเงินเดือนเป็น NULL ระบบยังตัดสินไม่ได้ว่ามากกว่าหรือเท่ากับ 0 หรือไม่ จึงไม่ถูก CHECK ปฏิเสธ หากต้องมีเงินเดือนเสมอ ให้ใช้ NOT NULL ร่วมด้วย

ทำงานอัตโนมัติเมื่อมีการเพิ่ม แก้ไข หรือลบข้อมูล
Statement Trigger ทำหนึ่งครั้งต่อคำสั่ง เช่น UPDATE หนึ่งคำสั่ง ส่วน Row Trigger มี FOR EACH ROW และทำหนึ่งครั้งต่อแถวที่คำสั่งนั้นเปลี่ยน ดังนั้น UPDATE ครั้งเดียวที่แก้พนักงาน 3 คน จะทำให้ Row Trigger ทำงาน 3 ครั้ง
คำสั่งStatement TriggerRow Trigger
UPDATE กระทบ 1 แถวทำ 1 ครั้งทำ 1 ครั้ง
UPDATE กระทบ 3 แถวทำ 1 ครั้งทำ 3 ครั้ง
UPDATE ไม่พบแถวยังเป็นเหตุการณ์คำสั่ง จึงทำ 1 ครั้งทำ 0 ครั้ง เพราะไม่มีแถว
ถ้าคำสั่งแก้ข้อมูล 3 แถว และมี Trigger ครบทั้ง 4 แบบ จะเริ่มด้วย BEFORE Statement หนึ่งครั้ง จากนั้นแต่ละแถวจะผ่าน BEFORE Row และ AFTER Row แล้วจบด้วย AFTER Statement หนึ่งครั้ง แต่ไม่ควรเดาว่าระบบจะเลือกแถวของพนักงานคนใดก่อน
สำคัญมาก
AFTER หมายถึงหลังการแก้แถวหรือหลังคำสั่งนั้นทำงาน ไม่ได้หมายถึงหลัง COMMIT ยืนยันแล้ว หากยังไม่ COMMIT แล้วสั่ง ROLLBACK การแก้ข้อมูลและประวัติที่ Trigger ปกติบันทึกในงานเดียวกันจะถูกยกเลิกด้วย

24 คำถามพร้อมแนวตอบ
1. เงินเดือนห้ามติดลบ ใช้แค่ NUMBER พอไหม?
ไม่พอ NUMBER กำหนดชนิด ไม่ได้ห้ามค่าติดลบ ใช้ CHECK (salary >= 0) และเพิ่ม NOT NULL หากต้องมีค่าเสมอ
2. UNIQUE กับ PRIMARY KEY เหมือนกันหรือไม่?
ทั้งคู่ค่าหรือชุดค่าที่กำหนดต้องไม่ซ้ำกับแถวอื่น แต่ PK ห้าม NULL ด้วย และตารางมี PK หนึ่งชุด ส่วน UNIQUE มีได้หลายชุด
3. เพิ่มพนักงาน department_id = 99 แต่แม่ไม่มี 99 จะเกิดอะไร?
ถ้า FK บังคับอยู่ คำสั่งเพิ่มล้มเหลว เพราะค่า FK ไม่ตรงกับคีย์แม่ หากเป็น NULL และคอลัมน์อนุญาต NULL จึงเป็นอีกกรณีหนึ่ง
4. ลบแม่ด้วย CASCADE ต่างจาก SET NULL อย่างไร?
CASCADE ลบแถวลูกที่อ้างแม่ตามไปด้วย ส่วน SET NULL เก็บแถวลูกและเปลี่ยนเฉพาะ FK ที่อ้างแม่เป็น NULL; ต้องอนุญาต NULL
5. ลบลูกคนสุดท้ายแล้วลบแม่ เป็น CASCADE หรือ Pendant DELETE?
เป็นแนวคิด Pendant DELETE ตามสไลด์ ทิศทางต่างจาก DELETE CASCADE ซึ่งเริ่มจากลบแม่แล้วลบลูก ไม่ใช่ตัวเลือก FK มาตรฐาน Oracle
6. ล็อกอินสำเร็จแล้ว DELETE ไม่ได้ เป็นเรื่องใด?
Authentication ผ่านแล้ว แต่ Authorization ไม่อนุญาต DELETE ต้องแยกตัวตนกับสิทธิ์

CREATE ROLE role_name; สร้าง Role ส่วน GRANT role_name TO user_name; มอบ Role ให้ผู้ใช้
8. ถ้าต้องรู้ว่าใครแก้เงินเดือนเมื่อวาน ต้องดูอะไร?
ดูประวัติการใช้งานหรือประวัติการแก้ไข ที่บอกว่าใครแก้ตารางใด เวลาไหน จากค่าเดิมเป็นค่าอะไร โดยต้องตั้งให้เก็บประวัติเรื่องนั้นไว้ก่อนเกิดเหตุ

Actual RPO = 8 นาที และ Actual RTO = 40 นาที ถ้าเป้าคือ RPO 10 และ RTO 45 นาที ถือว่าผ่านทั้งสองด้าน

CASCADEให้การเปลี่ยนข้อมูลมีผลตามไปยังแถวที่อ้างถึง ใน ON DELETE CASCADE เมื่อลบแถวแม่ จะลบแถวลูกที่อ้างแถวนั้นด้วย
CHECKกฎตรวจเงื่อนไขของข้อมูล เช่น CHECK (salary >= 0) ป้องกันเงินเดือนติดลบ แต่ยังต้องใช้ NOT NULL หากห้ามไม่มีค่า
COMMITยืนยันการเปลี่ยนข้อมูลในงานปัจจุบัน หลังจากนี้ ROLLBACK ปกติจะยกเลิกรายการที่ยืนยันแล้วไม่ได้
Constraintกฎที่ตั้งไว้ในตารางให้ฐานข้อมูลตรวจ เช่น ห้ามค่าซ้ำ ห้ามไม่มีค่า หรือห้ามเงินเดือนติดลบ
Cursorตัวช่วยอ่านผลลัพธ์จากคำสั่งค้นข้อมูล เช่น อ่านและจัดการทีละแถว
DBAผู้ดูแลฐานข้อมูล เช่น กำหนดสิทธิ์ ตรวจปัญหา และวางแผนสำรองข้อมูล
DBMSโปรแกรมที่จัดการฐานข้อมูล เช่น Oracle หรือ PostgreSQL
DDLคำสั่งสร้างหรือแก้โครงสร้าง เช่น CREATE TABLE สร้างตาราง และ DROP TABLE ลบตาราง
DMLคำสั่งเปลี่ยนรายการข้อมูล เช่น INSERT เพิ่ม UPDATE แก้ และ DELETE ลบ
Dependencyสิ่งที่ต้องใช้หรือทำให้ตรงกัน เช่น ตารางชำระเงินอ้างถึงคำสั่งซื้อ จึงต้องตรวจทั้งสองตารางเมื่อกู้ข้อมูล
Failoverสลับให้ระบบสำรองรับงานแทน เมื่อระบบหลักใช้ไม่ได้
Foreign Key (FK)คอลัมน์หรือชุดคอลัมน์ที่ใช้อ้างถึงข้อมูลที่มีอยู่ เช่น รหัสแผนกในตารางพนักงานอ้างถึงตารางแผนก
Immutable Backupชุดสำรองที่ตั้งให้แก้ไขหรือลบไม่ได้ในช่วงเวลาที่กำหนด
Incremental Backupสำรองเฉพาะส่วนที่เปลี่ยนตั้งแต่ชุดสำรองที่ใช้เป็นจุดอ้างอิง
Indexดัชนีที่ช่วยให้ฐานข้อมูลค้นหาแถวได้เร็วขึ้น โดยไม่ต้องอ่านทุกแถวเสมอไป
Least Privilegeให้สิทธิ์เท่าที่จำเป็นต่อหน้าที่ เช่น ผู้ที่ดูรายชื่ออย่างเดียวไม่ต้องได้สิทธิ์ลบ
Logบันทึกเหตุการณ์หรือการเปลี่ยนแปลง ในบทกู้ข้อมูลหมายถึงบันทึกที่ระบบใช้ช่วยกู้การเปลี่ยนข้อมูล
Log Gapบันทึกการเปลี่ยนแปลงขาดหายไปบางช่วง ทำให้กู้ต่อผ่านช่วงนั้นจากสำเนาเดิมไม่ได้ตามปกติ
NULLไม่มีค่าที่ระบุ อาจหมายถึงยังไม่ทราบหรือไม่เกี่ยวข้องตามการออกแบบ ไม่ใช่เลข 0
Parameterค่าที่รับเข้าหรือส่งกลับจากชุดคำสั่ง เช่น รหัสพนักงานและจำนวนเงินใน Procedure เพิ่มเงินเดือน
PITRการกู้ข้อมูลกลับไปยังเวลาที่เลือก เช่น เวลาก่อนเผลอลบข้อมูล
Primary Key (PK)คอลัมน์หรือชุดคอลัมน์ที่ระบุแต่ละแถวได้แน่นอน เช่น รหัสพนักงาน ต้องไม่ซ้ำและห้ามเป็น NULL
Recoveryการกู้ให้ข้อมูลกลับไปถึงเวลาที่ต้องการและใช้งานได้ถูกต้อง อาจต้องใช้บันทึกการเปลี่ยนแปลงต่อจากไฟล์สำรอง
Recovery Targetเวลาหรือจุดที่ต้องการกู้ข้อมูลกลับไปให้ถึง เช่น 10:14 ก่อนเกิดการลบผิดเวลา 10:15
Restoreการนำไฟล์หรือข้อมูลจากชุดสำรองกลับมา ยังอาจต้องกู้ต่อและตรวจข้อมูลก่อนเปิดใช้
Retentionระยะเวลาที่กำหนดให้เก็บสำเนาย้อนหลัง เช่น เก็บไว้ 30 วัน
Roleชุดสิทธิ์ที่ตั้งชื่อไว้แล้วมอบให้ผู้ใช้ได้ เช่น ชุดสิทธิ์อ่านข้อมูลฝ่ายบุคคล
ROLLBACKยกเลิกการเปลี่ยนข้อมูลที่ยังไม่ได้ COMMIT ในงานปัจจุบัน
RPOกำหนดว่ายอมให้ข้อมูลหายย้อนหลังจากเวลาเกิดเหตุได้นานที่สุดเท่าไร เช่น ไม่เกิน 10 นาที
RTOกำหนดว่าระบบหยุดได้นานที่สุดเท่าไร ก่อนต้องกลับมาใช้งานได้ เช่น ไม่เกิน 45 นาที
Runbookเอกสารบอกขั้นตอนทำงานที่ทำตามได้ เช่น กู้ไฟล์ใดก่อน ต้องตรวจอะไร และใครเป็นผู้รับผิดชอบ
Schemaใน Oracle คือกลุ่มตาราง View และสิ่งอื่นในฐานข้อมูลที่เป็นของผู้ใช้รายหนึ่ง
Statementคำสั่งหนึ่งชุด เช่น SELECT หนึ่งคำสั่ง หรือ UPDATE หนึ่งคำสั่ง
Stored Procedureชุดคำสั่งที่ตั้งชื่อและเก็บไว้ในฐานข้อมูล เมื่อเรียกชื่อจึงทำงาน เช่น raise_salary ใช้เพิ่มเงินเดือน
Transaction / ธุรกรรมงานที่มีการเปลี่ยนข้อมูลหนึ่งรายการหรือหลายรายการ แล้วเลือกยืนยันด้วย COMMIT หรือยกเลิกด้วย ROLLBACK ร่วมกัน
Triggerชุดคำสั่งที่ฐานข้อมูลเรียกเองเมื่อเกิดเหตุการณ์ที่กำหนด เช่น บันทึกประวัติเมื่อเงินเดือนเปลี่ยน
Undoข้อมูลเดิมที่ระบบเก็บไว้เพื่อใช้ย้อนการเปลี่ยนแปลง หรืออ่านข้อมูลก่อนถูกแก้ตามที่ระบบรองรับ
Viewชื่อที่เก็บคำสั่งค้นข้อมูลไว้ในฐานข้อมูล เรียกใช้เหมือนตารางได้ โดย View ปกติไม่ได้เก็บสำเนาผลลัพธ์เอง
